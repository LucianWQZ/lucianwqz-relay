## 3. 规范化后的最终非 Graph 目标

### 方法与策略

- Eagle3、DFlash、eligible DSpark 是主要方法。
- `draft_window_size` 未配置时沿基线行为；Window OFF 与 forced-OFF 不创建 Window runtime、owner、view、lane 或额外 event。
- MTP 强制关闭 Draft Window，但不关闭 MTP 投机方法。
- 共训 DeepSeek-V4 DSpark 强制关闭 Draft Window；必须绑定实际 target/draft checkpoint、`config.json`、规范化 `model_type`/`architectures` 和运行时 speculator 身份。路径前缀或模型名相似不能证明共训关系。
- plain Eagle、DFlash2、dynamic-K 保持明确的 `NEEDS_DECISION` 或上游能力状态；不得遗漏，也不得自行扩成未经确认的新产品任务。

### 数据与正确性契约

- canonical Full block table、Full slot/write、绝对 positions、Target metadata 与 Target 行为保持基线语义。
- Window 只改变 Draft 的允许读取视图和读取长度；读取 backing 与 Full 写侧身份隔离。
- 以当前请求、当前 generation、当前 rejection 后 exact 长度规划，不能用 upper、valid columns、旧 generation 或估计接受数替代。
- 数学保持 `H = E + future_offset`、`S = floor(max(H-W,0)/B)*B`、`V = E-S`；`B` 必须来自真实几何。
- request finish/add/reorder、同 row 替换、preempt/resume、prefix block 复用和 generation 变化必须更新实际消费的数据。
- 未知 completion 或未 join 的 late reader 不能让 backing 被下一 generation 覆写。

### 必需特性与组合

- FlashComm、SP、Async、chunked prefill、prefix cache、多请求、混合到达和真实生命周期。
- TP/DP/PP/PCP/DCP/EP 按实际 required route；GLM 历史主要路线保持 TP16/DP1/EP/K8/Async，Draft eager、Target 已有 Graph 配置。
- legacy DSA-CP 在固定基线被启动 guard 拒绝，是最终需求与基线能力之间的真实缺口。不能删 guard，不能用 PCP 替代，也不能从范围删除。
- backend/provider 以实际 Draft consumer 和 builder 为准；Target 的 DSA 架构不能证明 Draft 使用 DSA。
- multi-group 按 required model 的真实 gid/layout/geometry 验证，不制造全参数笛卡尔积。
- Draft Window Graph 由独立 Graph 线路推进；本非 Graph 交付仍需回归共享代码影响的已有 Target Graph、MRV1 与 OFF 路径。

### 设备与性能

- A3 是主要设备验收环境。本地 Host PASS 不等于 A3 PASS。
- 性能使用同一候选、同权重、同环境比较官方 base OFF、候选 OFF、候选 ON。
- 历史 GLM5.2 + DSpark 路线为 TP16/DP1/EP/K8/Async、输出 2000，十进制输入目标 `16000/32000/64000/128000`，OFF/W1024 共 8 单元；`16384/131072` 只能是历史名义标签。
- 正式性能前必须通过源码/native/model/rank 身份、同窗口数值、适用 Full-write、资源与长度预算门槛。诊断 observer/oracle/profiler 与正式性能分进程。
- 历史收益、退化或 `NO_MEASURABLE_DIFFERENCE` 仅绑定其原始版本和配置，不能继承为新 SHA 结论。

## 5. 验收状态词

- `SOURCE_IMPLEMENTED`：源码已实现，不含 Host、设备或性能结论。
- `HOST_VERIFIED`：绑定精确 tree 的可执行 Host 检查通过；不替代 native/NPU。
- `A3_VERIFIED_FOR_DECLARED_SCOPE`：只覆盖声明的 model/method/backend/topology/feature/case。
- `DRAFT_PR_READY` / `CREATED`：代码和说明达到相应发布状态；不代表合入。
- `READY_FOR_REVIEW`：required scope、A3、CI 和文档达到正式评审门槛。
- `MERGED`：只有远端事实才能使用。

当前候选不能标记 `A3_VERIFIED_FOR_DECLARED_SCOPE`、`READY_FOR_REVIEW` 或完整非 Graph 验收完成。
