## 6. 首个有界开发问题

### DW-A01：固定版本 exact-length consumer / D2H 契约收敛

选择依据：当前 HEAD 没有 A01 后续提交；ArchitectureReview 将其判为 `ARCHITECTURE_BLOCKED`，并且固定 MRV2 设计明确 async-first。该问题阻塞 Eagle/GQA/DFlash 等 required route 的本地架构门槛，优先级高于扩大 case 数。

第一阶段只做事实核验，不立即泛化实现：

1. 从固定源码列出 `draft_window_runtime.py::metadata_callback` 的 exact 来源与每 proposal/AR step 次数。
2. 使用已有 `A01_DEVICE_PROBE_PLAN.json`/helper，在真实固定 torch_npu/CANN/native 环境收集算子 schema。
3. 对 GQA、ordinary MLA、DSA/SFA 的真实 builder 分别确认哪些接受 device exact、哪些 CPU consumer 需要 list/chunk/capacity。
4. 做最小真实调用与动态 device length 数值对比；短 trace 区分 Window D2H、基线 copy、builder `.tolist`、H2D staging、observer 自身开销。
5. 保存当前反例：不得用 upper 替 exact；不得用上一 generation；不得用 `non_blocking=True` 后立即 CPU 读取伪装修复。

完成条件：得到一份逐 consumer 的接口事实表，并选择一个最小可审阅方案：复用同 generation 已完成 CPU exact、局部 device plan/projection，或明确的 device exact / host capacity descriptor。若固定 ABI 不支持，提交最小跨仓接口提案，列替代方案与影响面。

实现阶段只改必要文件，预期重点：

- `vllm_ascend/worker/v2/spec_decode/draft_window_runtime.py`
- `draft_window_plan.py`、`draft_window_read.py`
- 实际 GQA/MLA/DSA/SFA builder consumer
- Eagle3/DFlash/DSpark speculator 调用点
- 对应 targeted tests 与公开设计文档

最小 Host 验证：数学边界、current-generation exact、rejection、K/K+1、Eagle all-step、OFF zero-state、request reorder/reuse、consumer fallback 不丢 exact。需要 NPU 的验证：schema、最小 native call、动态长度数值、D2H/CPU stall/overlap trace。

若失败，必须回传实际 schema、调用 argv、输入 layout/dtype/shape、trace、异常栈和源码/runtime identity；不能用现场热补丁继续跑正式性能。

每轮遵循：一个有界问题 → 必要本地检查 → 有意义的 signed-off commit → 固定源码/环境实验 → 保存成功与失败 → 更新状态和下一问题。不要为了频率制造空提交。生产修改后更新 SHA/tree、失效证据列表、server input 和 handoff；未验收 candidate 不称“最终 PR”。

## 9. 实验结果合同

每个 `run_id/attempt` 至少保存：双仓 SHA/tree/diff、native/build/import 身份、模型/config/hash、资源合同、完整命令与环境变量（脱敏）、per-rank worker/backend/gid/geometry、requested/effective/actual features、原始 logs/oracle/trace、结果与未执行原因。功能 PASS、device correctness、overlap、performance、完整范围分别报告。

## 10. 停止条件

- source/import/native/model/rank/resource 不匹配。
- native 数值或 Full-write/Target invariant 损坏。
- unknown completion backing 被复用，或存在未 join final reader。
- 实验需要生产修改：保存 evidence，回 `dev/pr` 修改并生成新 SHA，再重新绑定。
- 模型/driver/team CLI 缺失：只阻塞对应 case，继续不依赖的工作。
